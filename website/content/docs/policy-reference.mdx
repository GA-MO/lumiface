A policy is resolved per request as **environment defaults → preset → project overrides**. Server fields are applied by the verification pipeline; `client.*` fields are sent to the app in every session as `client_config` and applied by the Flutter and React SDKs while running the challenges. Any field can be overridden:

```bash
curl -X PUT $SERVER/v1/policy -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"preset": "strict", "overrides": {"match_threshold": 0.5, "client": {"challenge_timeout_ms": 8000}}}'
```

The same names, upper-cased, are the environment variables that set the defaults of the `balanced` preset (server fields only; client defaults live in the code).

## Client fields

| Field | Type | Default | Description |
|---|---|---|---|
| `client.align_hold_ms` | int | `600` | Face must stay aligned this long before the first frame. |
| `client.min_face_width_fraction` | float | `0.28` | Face box width / frame width lower bound. Scaled down with the upper bound when the oval's start is narrower than max_face_width_fraction (a landscape preview), so the band keeps its proportion. |
| `client.max_face_width_fraction` | float | `0.48` | Face box width / frame width upper bound. Under the face_move start (move_start_max_ratio x the oval), so "move back" happens while aligning and the hold before the walk stops the person from backing off further. |
| `client.center_tolerance` | float | `0.18` | Allowed offset of the face centre from the frame centre. |
| `client.neutral_max_yaw` | float | `15` | Max |yaw| in degrees for a neutral frame. |
| `client.neutral_max_pitch` | float | `15` | Max |pitch| in degrees for a neutral frame. |
| `client.challenge_timeout_ms` | int | `10000` | Give up on the oval after this long. |
| `client.face_lost_grace_ms` | int | `1500` | Fail when no face is seen for this long. |
| `client.oval_min_fill` | float | `0.85` | face_move: face width / oval width that counts as fitted (centred within a fifth of the oval). |
| `client.oval_hold_ms` | int | `500` | face_move: the face must stay fitted this long. |
| `client.move_start_max_ratio` | float | `0.8` | face_move: face width / oval width the challenge must start below, so the move is a real one. |
| `client.settle_after_challenge_ms` | int | `400` | Pause after the oval is filled before the flash. |
| `client.settle_after_flash_ms` | int | `800` | Pause after the last flash colour before neutral_end. |

## Presets

Each preset is a set of overrides on top of the environment defaults. `GET /v1/policy/presets` returns the same data with the fully resolved policy per preset.

### balanced

Calibrated defaults from the environment: move into the oval, then the flash. Phone-tested attendance check-in.

_No overrides: the environment defaults as they are._

### strict

Higher match and anti-spoof bars, a longer walk into a fuller oval, tighter flash correlation. Access control, KYC.

| Field | Value |
|---|---|
| `match_threshold` | `0.55` |
| `spoof_threshold` | `0.6` |
| `spoof_hard_floor` | `0.35` |
| `cvpr_threshold` | `0.4` |
| `move_min_growth` | `1.4` |
| `flash_min_correlation` | `0.7` |
| `client.oval_min_fill` | `0.9` |
| `client.move_start_max_ratio` | `0.5` |

### relaxed

Lower bars, the flash records scores only, more time for the oval. Low-risk flows, poor lighting, kiosks.

| Field | Value |
|---|---|
| `match_threshold` | `0.4` |
| `spoof_hard_floor` | `0.2` |
| `cvpr_threshold` | `0.2` |
| `flash_enforce` | `false` |
| `max_challenge_ms` | `15000` |
| `client.challenge_timeout_ms` | `15000` |
| `client.face_lost_grace_ms` | `2500` |
| `client.min_face_width_fraction` | `0.2` |

### emulator

Flash off and smaller faces accepted. Android emulator with a webcam, CI demos.

| Field | Value |
|---|---|
| `flash_enforce` | `false` |
| `spoof_hard_floor` | `0.2` |
| `min_face_size` | `60` |
| `client.min_face_width_fraction` | `0.2` |
