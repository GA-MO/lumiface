## Install

```json
{
  "dependencies": {
    "@lumiface/react": "github:GA-MO/lumiface#path:packages/lumiface-react",
    "@mediapipe/tasks-vision": "^1.0.1"
  }
}
```

The package ships TypeScript source (`src/`), so Next.js needs `transpilePackages: ["@lumiface/react"]`; Vite needs nothing. `@lumiface/react/core` is the browser-free part (client, controller, detectors, strings) for tests and workers.

## The view

```tsx
import { LumifaceClient, LumifaceView, TH, sessionFromJson } from "@lumiface/react";

const client = new LumifaceClient({ baseUrl: "https://faces.example.com" });

export function LoginWithFace({ userId }: { userId: string }) {
  return (
    <div style={{ height: "70vh" }}>
      <LumifaceView
        client={client}
        sessionProvider={async () => sessionFromJson(await fetch("/api/face/session", { method: "POST" }).then((r) => r.json()))}
        strings={TH}
        theme={{ guideShape: "roundedRect", guideActive: "#2dd4bf" }}
        onResult={(r) => (r.ok ? signIn(r.verificationId) : toast(r.reasonCode))}
        onDone={() => close()}
      />
    </div>
  );
}
```

It fills its parent, so size the parent. Props mirror the Flutter view.

## The browser holds no secret

`LumifaceClient` takes a URL and nothing else — there is no option for the project key — and it can do exactly
two things: upload the frames of a session it was handed, and upload one enrolment photo with a token it was
handed. `/api/face/session` above is your backend route that produces the session, with two REST calls:

```ts
// your backend (Node shown; any language — see examples/backend for a complete one in Python)
const LUMIFACE = "https://faces.example.com";
const KEY = { "X-API-Key": process.env.LUMIFACE_KEY! };

app.post("/api/face/session", auth, async (req, res) => {
  const r = await fetch(`${LUMIFACE}/v1/sessions`, { method: "POST", headers: { ...KEY, "Content-Type": "application/json" },
    body: JSON.stringify({ subject_id: req.user.id, purpose: "login" }) });
  res.json(await r.json());                                   // straight to the browser
});

app.post("/api/face/done", auth, async (req, res) => {
  const status = await (await fetch(`${LUMIFACE}/v1/sessions/${req.body.sessionId}`, { headers: KEY })).json();
  if (status.result?.ok && status.subject_id === req.user.id) await signIn(req.user);   // the decision is here
  res.sendStatus(204);
});
```

There is no backend SDK on purpose: the key's side of the API is a handful of REST calls
([reference](/docs/api)), and `@lumiface/react` then contains nothing a key could leak through. The server
also refuses the key from any browser origin but localhost, so a key that ends up in a bundle fails loudly.

Enrolment from the camera is the same shape with `flow="enroll"` and an `enrolTokenProvider` that asks your
backend for a single-use token (`POST /v1/subjects/tokens` there).

## The hook

`useLumiface(options)` runs the camera and the controller without any markup:

```tsx
const fg = useLumiface({ client, sessionProvider: faceSession });
return (
  <div ref={fg.mountVideo} style={{ position: "relative", height: 480 }}>
    <p>{messageFor(EN, fg.state, fg.flow)}</p>
    {fg.state.phase === "flash" && <div style={{ position: "absolute", inset: 0, background: `#${fg.state.flashColor}` }} />}
  </div>
);
```

It returns `state`, `signal`, `flow`, `ready`, `error`, `controller`, `source`, `mountVideo` (ref callback that mounts the `<video>`), `start()` and `cancel()`. Options: `client`, `flow`, `sessionProvider`, `enrolTokenProvider`, `config`, `clientInfo`, `camera`, `autoStart`, `onResult`, `onStateChanged`, `onFlashChanged`. The effect re-runs when `client` or `flow` change.

## Headless

`FaceVerifyController` and `FaceEnrollController` take a `FaceSignalSource` (`subscribe(listener)`) and a `FrameCapturer` (`captureJpeg(): Promise<Blob>`), expose `state`, `subscribe`, `start`, `cancel`, `dispose`. `MediaPipeSource` implements both over `getUserMedia` + FaceLandmarker and owns a `<video>` you mount anywhere. The test suite (`test/controller.test.ts`) drives the controller with synthetic signals exactly like the Flutter tests.

## Demo

```bash
bun install && bun run dev:react     # http://localhost:3010
```

Check-in, login (themed), liveness only, enrol from camera, custom overlay; the server URL and subject id are remembered in `localStorage`. The key lives in `examples/backend`, which the page reaches through the `/api` proxy.
