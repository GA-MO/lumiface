## Done

- Phase 0–3: server, Flutter package, Android and iOS, calibration scripts.
- Phase 4: hardening (CVPR gate, parallax, screen flash with locality, server smile re-check), tested on a Galaxy S25+.
- Phase 5: Flutter web through MediaPipe FaceLandmarker, verified on Chrome desktop.
- Phase 6: React SDK (`@lumiface/react`) with the same controller, MediaPipe source, view, hook and tests.
- SaaS shape: projects with API keys, per-project policy with presets and overrides, `client_config` in every session, admin endpoints, this documentation site with `llms.txt`.

## Open

- Flash thresholds were set from one person, one phone and two replays; confirm on two more people and darker phones, and try replay from a matte screen, a tablet and a monitor.
- MiniFASNet gives real faces as low as 0.31 on the S25+ in some frames (hard floor 0.30); lower `spoof_hard_floor` to 0.2 for a project if false rejects appear, CVPR and flash are the main gates.
- Smile thresholds come from two image pairs; watch `details.smile` on more people.
- iOS on a real iPhone has not been run since the rename; the yaw sign of the ML Kit source on iOS is unproven.
- MediaPipe yaw sign was checked on one Mac webcam; `yawSign: -1` is available if a camera disagrees.
- Safari on iOS with the Flutter web build is untested.
