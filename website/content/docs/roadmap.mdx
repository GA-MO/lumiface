## Done

- Phase 0–3: server, Flutter package, Android and iOS, calibration scripts.
- Phase 4: hardening (CVPR gate, parallax, screen flash with locality, server smile re-check), tested on a Galaxy S25+.
- Phase 5: Flutter web through MediaPipe FaceLandmarker, verified on Chrome desktop.
- Phase 6: React SDK (`@lumiface/react`) with the same controller, MediaPipe source, view, hook and tests.
- SaaS shape: projects with API keys, per-project policy with presets and overrides, `client_config` in every session, admin endpoints, this documentation site with `llms.txt`.
- Phase 7: device tokens. The key stays on the backend; devices hold a session token or a single-use enrol token; the backend reads the verdict with `GET /v1/sessions/{id}`.
- Phase 8: the stream. `WS /v1/sessions/{id}/stream`, frames the whole time, the server clocks and judges every challenge and the flash itself; `LumifaceClient` takes only a URL; `examples/backend` shows the REST side. Run on a Galaxy S25+ release build (real person 9/10, replayed video 0/11) and on Chrome with the React example (replay 0/4).

## Open

- Flash thresholds were set from one person, one phone and two replays; confirm on two more people and darker phones, and try replay from a matte screen, a tablet and a monitor.
- MiniFASNet gives real faces as low as 0.31 on the S25+ in some frames (hard floor 0.30); lower `spoof_hard_floor` to 0.2 for a project if false rejects appear, CVPR and flash are the main gates.
- Smile thresholds come from two image pairs; watch `challenge_<i>` in the verification details on more people.
- A phone streams about 6–7 fps, not 8: the pure-Dart JPEG encode costs ~150 ms a frame. Native encoding would close the gap.
- iOS native (ML Kit) ran on an iPhone 12 on 2026-09-18: real person 3/3 after two iOS-only fixes (the front camera's frames arrive mirrored, so the yaw sign flips; they arrive upright, so the JPEG must not be rotated again), replayed video 0/4. CPU on iOS is not measured yet.
- MediaPipe yaw sign was checked on a Mac webcam and an iPhone 12 front camera (Safari); `yawSign: -1` is available if a camera disagrees.
- iPhone 12 Safari, both SDKs (2026-09-18): real person 8/9 (one blink missed before the shut-eyes frame was sent at once), replayed video 0/5.
