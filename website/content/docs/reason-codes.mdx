---
title: Reason codes
description: Every code a verification, an enrolment or the SDK can end with, who raises it, and what the user should do.
---

## Verify pipeline (server)

| Code | Meaning | Usual fix |
|---|---|---|
| `OK` | passed | |
| `FRAME_COUNT` | no frames reached the server | client bug, network |
| `TIMING_ORDER` | the events did not follow the plan (missing, repeated, reordered) | client bug |
| `TIMING_TOO_FAST` | whole session under `min_session_ms` or a challenge under `min_challenge_ms`, on the server's clock | scripted client |
| `TIMING_TOO_SLOW` | a challenge over `max_challenge_ms` | retry |
| `FRAMES_STATIC` | the same bytes streamed again and again | a still image played as video |
| `NO_FACE` | no face in the frames of a window (`details.window`) | lighting, framing |
| `MULTIPLE_FACES` | more than one comparable face | one person in frame |
| `FACE_TOO_SMALL` | face box under `min_face_size` | move closer |
| `SPOOF` | MiniFASNet or CVPR gate failed (`details.gate`) | real face, no screen |
| `POSE_MISMATCH` | no frame in the turn or nod window shows the pose | perform the challenge |
| `EXPRESSION_MISMATCH` | the server saw no blink (eyes never closed and reopened) or no smile in the window | blink fully, smile wider |
| `FLASH_FAIL` | reflection did not follow the colours or the surroundings reflected as much as the face | full brightness, no screen |
| `NO_MATCH` | a frame below `match_threshold` against the subject | wrong person or bad enrolment |
| `INCONSISTENT` | frames not the same person | one person for the whole session |

## Enrolment (server)

`NO_FACE`, `MULTIPLE_FACES`, `FACE_TOO_SMALL`, `POSE_NOT_FRONTAL`, `SPOOF`, `SUBJECT_EXISTS`.

## HTTP level

`SESSION_NOT_FOUND`, `SESSION_USED`, `SESSION_EXPIRED`, `SUBJECT_NOT_FOUND`, `HELLO_INVALID`, `EVENT_INVALID`, `PAYLOAD_TOO_LARGE`, `ENROL_TOKEN_INVALID`, `ENROL_TOKEN_MISMATCH`, `EXTERNAL_ID_REQUIRED`, `TTL_INVALID`, `PROJECT_EXISTS`, `PROJECT_NOT_FOUND`, `UNKNOWN_PRESET`, `POLICY_INVALID`, `API_KEY_FROM_BROWSER` (a project key sent from a browser page other than localhost), and `HTTP_<status>` when the server answered without a code. `BAD_IMAGE` is a verify/enrol verdict for a frame that does not decode.

## SDK (device)

| Code | Meaning |
|---|---|
| `TIMEOUT` | a challenge ran past `challenge_timeout_ms`, or the session TTL passed |
| `FACE_LOST` | no face for longer than `face_lost_grace_ms` |
| `CANCELLED` | `cancel()` was called |
| `NETWORK_ERROR` | session or verify request failed |
| `CAPTURE_ERROR` | the camera could not deliver a frame |

Both SDKs map every code to a user-facing line in `LivenessStrings` (en, th); unknown codes are shown as is.
