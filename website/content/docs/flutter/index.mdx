## Install

```yaml
dependencies:
  lumiface:
    path: ../lumiface/packages/lumiface   # or a git url with a tag
```

- iOS: `NSCameraUsageDescription` in `Info.plist`, platform 15.5 or newer. Xcode 26 refuses pods that declare a deployment target under 15, so the example's `Podfile` pins every pod to 15.5 in `post_install`; copy that block.
- Android: `minSdk` 23 or newer. Release builds need no ProGuard work of yours: the package ships the keep rules ML Kit requires under R8 (without them face detection fails on every frame in release).
- Web: nothing to add; the MediaPipe glue is loaded from the package assets. See [Web](/docs/flutter/web).

## The view

```dart
FaceVerifyView(
  client: LumifaceClient(baseUrl: 'https://faces.example.com'),
  sessionProvider: () async => FaceSession.fromJson(await myApi.createFaceSession('E001')),
  strings: LivenessStrings.th,
  theme: FaceVerifyTheme.fromScheme(Theme.of(context).colorScheme),
  onResult: (VerifyResult r) { ... },
  onFlashChanged: (on) => ...,  // push brightness to max while the screen flashes
)
```

It fills its parent, so put it in a `Scaffold` body or any sized box. The result arrives once through `onResult`; the default overlay then shows a Done or Try again button that pops the route.

## The app holds no secret

`LumifaceClient` takes a URL and nothing else — there is no way to give it the project key — and it can do
exactly two things: upload the frames of a session it was handed, and upload one enrolment photo with a token it
was handed. Both come from your backend, which is the only place the key lives:

```dart
// app
FaceVerifyView(
  client: LumifaceClient(baseUrl: 'https://faces.example.com'),
  sessionProvider: () async {
    final r = await myApi.post('/face/session', {'user': 'E001'});   // your route, behind your login
    return FaceSession.fromJson(r);
  },
  onResult: (r) => myApi.post('/face/done', {'session': r.sessionId}),
)
```

```python
# your backend, any language: two REST calls with the key (Python shown; see examples/backend for the whole thing)
session = httpx.post(f"{LUMIFACE}/v1/sessions", headers=KEY, json={"subject_id": user.id, "purpose": "checkin"}).json()
return session                                   # → the app, as is

# later, when the app says it is done:
status = httpx.get(f"{LUMIFACE}/v1/sessions/{session_id}", headers=KEY).json()
if status["result"] and status["result"]["ok"]: mark_checked_in(user)
```

There is no backend SDK on purpose: the key's side of the API is a handful of REST calls
([reference](/docs/api)), and the packages the app depends on then contain nothing a key could leak
through. The server also refuses the key from any browser origin but localhost.

Enrolment from the camera is the same shape with `flow: FaceFlow.enroll` and an `enrolTokenProvider` that asks
your backend for a single-use token (`POST /v1/subjects/tokens` there).

The `VerifyResult` the app receives is for the UI; the decision is the `GET /v1/sessions/{id}` on your backend.

## The result

```dart
class VerifyResult {
  bool ok;
  String mode;            // verify | liveness | enroll
  String reasonCode;      // OK or a code from the reason-codes page
  VerifyScores scores;    // match, spoof, consistency (null when not applicable)
  int? verificationId;    // set on success for verify and liveness
  String? sessionId;      // hand it to your backend for GET /v1/sessions/{id}
  Subject? subject;       // set on success for enroll
  String? message;        // detail for client-side codes (NETWORK_ERROR, CAPTURE_ERROR)
}
```

## The client

`LumifaceClient` is the device side only: `openStream(session)` returns a `VerifyStream` (`plan`, `sendFrame`, `event`, `end`, `close`) that the controller drives, and `enroll(photoJpeg:, enrolToken:)`. Errors other than a verdict throw `LumifaceException(reasonCode, details)`.

## Theme

`FaceVerifyTheme` covers `backgroundColor`, `maskColor`, `guideColor` / `guideActiveColor` / `guideSuccessColor` / `guideFailedColor`, `guideShape` (`oval`, `roundedRect`, `none`), `guideWidthFraction`, `guideAspectRatio`, `guideCenterY`, `guideStrokeWidth`, `progressColor`, `progressBackgroundColor`, `messageStyle`, `messagePadding`, `showProgress`, `showButtons`. `FaceVerifyTheme.fromScheme(colorScheme)` derives the colours from your Material theme.

## Strings

`LivenessStrings.en` and `LivenessStrings.th`. `copyWith` replaces single lines and merges `reasons`, so a login screen can say "Welcome back" instead of "Verified" without redefining the rest:

```dart
strings: LivenessStrings.en.copyWith(success: 'Welcome back'),
```
