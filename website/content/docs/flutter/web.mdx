title: Flutter web
description: The same package on Chrome and Safari through TensorFlow.js BlazeFace; what changes and what to watch.
---

`flutter build web` works out of the box. On the web the package uses `BlazeFaceCameraSource`:

- `getUserMedia` opens the front camera at 1280×720 and shows it mirrored.
- A small ES module in the package assets (`assets/lumiface_blazeface.js`) imports `@tensorflow/tfjs-core`, the WASM and CPU backends and `tfjs-converter` (4.22.0) from jsDelivr, loads the short-range BlazeFace graph model from the package assets (`assets/face_detection_short/`, 280 KB) and returns one JSON signal per frame. The WASM backend is tried first, the CPU backend is the fallback.
- The signal is the largest face box; BlazeFace reports no head angles, so `yaw` and `pitch` are null and the `lookStraight` hint never fires on the web. The controller and the thresholds are the same as on the phones.
- The stream the server judges is a MediaRecorder recording (WebM/VP8 where the browser has it, MP4/H.264 on Safari), cut every 250 ms at 1.5 Mbps (`chunkMs`, `videoBitsPerSecond`).

## Self-hosting

Pass URLs when you construct the source yourself:

```dart
FaceVerifyView(
  client: client,
  sourceFactory: () => BlazeFaceCameraSource(
    tfjsUrl: '/vendor/tfjs/',                          // folder holding tfjs-core@<v>/+esm etc.
    wasmUrl: '/vendor/tfjs-backend-wasm/dist/',         // the .wasm binaries
    modelUrl: '/vendor/face_detection_short/model.json',
  ),
  ...
)
```

No COOP/COEP headers are needed; without them the WASM backend runs single-threaded.

## Things that differ from a phone

- **Flash response is lower.** A laptop screen lights the face less than a phone held close: a MacBook in a bright room measured response 2.05 against the default minimum of 2.0. Use the `relaxed` preset while developing on a laptop, or lower `flash_min_response` for a web-only project.
- **The guide relates to the camera frame, not the viewport.** A landscape webcam cropped into a portrait box hides its sides; the user should sit centred in front of the camera.
- **Exposure lock is unavailable** in the browser; the settle window after the flash still keeps tinted frames out of `neutral_end`.
- The camera needs `https` or `localhost`.

The BlazeFace source has not yet been run in front of a camera in Flutter web; the same decoder in the React SDK was verified on 2026-09-18 in headless Chrome on a sample face (WASM backend, 7 ms a frame). The earlier MediaPipe source was verified on Chrome desktop and iPhone 12 Safari with the gesture flow of the time.
