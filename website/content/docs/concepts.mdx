## Project

A tenant. It owns an API key (`X-API-Key`, backend only), its subjects, its verifications and its [policy](/docs/server/policy). Devices authenticate with short-lived tokens the backend obtains with that key: a `session_token` per session and an enrol token per enrolment. Projects are created with the admin key (`POST /v1/projects`), or bootstrapped from the environment on first start.

## Subject

Whoever can be verified: an employee, a customer, a member. Identified by your own `external_id`; the server stores one ArcFace embedding per subject, never the photo.

## Session and flow

A session is one attempt. It holds the challenges, the flash colours, a TTL and the client tunables. The **flow** decides what the session proves:

| Flow | subject_id | Proves |
|---|---|---|
| `verify` | required | a live person who matches the enrolled subject |
| `liveness` | omitted | a live person (kiosks, gating a form, pre-checks) |
| `enroll` | your id | captures one frontal frame and enrols it (SDK-side; the server sees a normal enrolment) |

`purpose` is a free label (`checkin`, `login`, `kiosk`, ...) stored with the verification for filtering; it does not change the checks.

## Stream

The app opens a WebSocket for the session, receives the plan (challenges, flash colours) and then streams JPEG frames continuously, about eight a second, while it runs the plan. Events (`aligned`, `challenge_done`, `flash`, `flash_end`) mark the boundaries. The server stamps everything with its own clock, runs its own landmarks inside each window to confirm the blink, smile, turn or nod, reads the flash reflection from the frames of each colour window, and only then scores anti-spoof, identity and consistency on the key frames it picked. The device's detectors exist to guide the person; they decide nothing.

## Policy

Every threshold and every client tunable, resolved per request as environment defaults → preset → overrides. Server fields drive the pipeline; `client` fields are sent to the app in `client_config` and applied by the SDKs. See the [policy reference](/docs/policy-reference).

## Who checks what

| Check | Where | Beats |
|---|---|---|
| Blink timing, smile hold, turn and nod angles | device (guidance) and **server** (from its own landmarks on the streamed frames) | scripted photos, slow videos, a patched client that skips its checks |
| Nose parallax during a turn | device | a flat print or screen rotated in front of the camera |
| Timing order and durations | server, on its own clock (device stamps only place frames into windows) | replayed recordings responding at random times, forged timestamps |
| A frozen or repeated feed | server | a still image streamed as video |
| MiniFASNet ensemble | server | prints, screens with visible bezels |
| CVPR-2024 ResNet50 on a face crop | server | bezel-free screen replay |
| Screen-flash reflection and locality | server | any replay that cannot know the colours, phone screens that reflect the whole sheet |
| Smile re-check from 68 landmarks | server | rigid latex or silicone masks |
| ArcFace match and cross-frame consistency | server | the wrong person, swapping people mid-session |
